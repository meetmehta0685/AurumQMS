## Product and visual direction

Use one product identity: **QMS Operations**, with two suites:

- **Care Operations** for patient, doctor, admin, lab, and pharmacy workflows.
- **Stay Operations** for guest and staff workflows.

The interface direction is a calm operational command center: warm ivory and
ink foundations, eucalyptus/teal for care, oxidized-gold for hospitality, and
vermilion only for urgent states. Retain the existing Manrope + Fraunces + IBM
Plex Mono font pairing, but apply it systematically. Favor strong hierarchy,
compact data surfaces, clear status language, generous page margins, and
restrained state-transition motion. Avoid generic blue hospital dashboards,
purple gradients, nested cards, and decorative copy that describes the UI.

## Findings considered and rejected

- Replacing Supabase: rejected. The current schema, auth, and RLS investment is
  substantial; making operations server-authoritative is lower risk.
- Maintaining both fake and real Selenium tests: rejected. The fake test proves
  no browser behavior and creates false confidence.
- Redesigning every page before backend repair: rejected. It would duplicate UI
  work when workflow contracts change and make failures harder to isolate.
